# Backup

## Purpose
Implements "Feature 0" disaster recovery: `kycap/3` container encapsulation (`.kycap`) from `github.com/Busness-app/ky-primitives/capsule`, sealed to the suite recovery public key received at KyRecovery pairing or pinned by hand, delivery of the sealed container to a local backup directory and to KyRecovery, the backup schedule, and automated sandboxed restore drills.

## Ownership
Owns backup payload collection (database snapshot, RSA signing key, encryption and secret keys, config manifest), the KyRecovery client (claim and deposit), loading and pinning the suite recovery public key (`recovery.pub`, key ID pinned in `system_settings`), the pairing record (`kyrecovery_url`, sealed `kyrecovery_token_enc`), the last deposit receipt (`kyrecovery_last_deposit`), the schedule (`backup_interval_sec`, `backup_last_attempt`), the local backup directory (`KYSIGNON_BACKUP_DIR`, `KYSIGNON_BACKUP_KEEP`), and sandboxed restore drill verification against a throwaway key. It holds no private key and no shares; custodian cards come from the KyRecovery ceremony.

## Local Contracts
- `ClaimPairing` sends `service_name` explicitly and it must be the value `Seal` is given (`cfg.AppName`): KyRecovery pins the claimed name and refuses every deposit whose manifest names another.
- `StoreRecoveryKey` is write-once per key; `StorePairing` runs after it and seals the token under `crypto.DeriveKey(EncryptionKey, "kysignon:setting:kyrecovery_token")`. `LoadPairing` reports `ErrNotPaired` unless key, URL and token are all present.
- `CollectSealable` snapshots the database through the live handle (`SnapshotTo`, `VACUUM INTO`); a missing database, signing key or deployment key is fatal, never skipped. Its output leaves the process only inside a sealed capsule.
- `Deposit` sends the container as `application/octet-stream` with the bearer token, accepts 200 or 201, and refuses a receipt whose digest, size or capsule ID do not describe the bytes sent. Wire and store errors wrap `ErrRemote`; a deposit that landed but whose receipt write failed wraps `ErrReceiptUnrecorded` and still returns the receipt. Deposits are single-flight per process.
- `RunBackup` is the one entry point for making a backup: it stamps the attempt, seals once, writes the local copy when `BackupDir` is set, then deposits when paired. A pinned key with neither destination is `ErrNoDestination`. `Outcome` turns any result into the audit action `admin.backup_run`, outcome and details, bounded by `AuditSafe`; every caller (route, scheduler, CLI) records through it.
- `WriteLocalCopy` writes `<AppName>-<capsule-id>.kycap` at 0600 through a temp file and rename, then prunes this instance's files beyond `BackupKeep`, newest first by mtime. Listing and pruning see only names with this instance's prefix; the operator's other files in the directory are untouchable. A local failure is carried in `Result.LocalError` and does not stop the deposit; the run errors only when every configured destination failed.
- The schedule is `Interval`: the admin's `backup_interval_sec` setting when present, else `KYSIGNON_BACKUP_DEPOSIT_INTERVAL`. `SetInterval` takes whole seconds and enforces 0 or `[config.MinBackupDepositInterval, MaxInterval]` before any conversion, so no value can wrap to zero; the route reads the schedule back and reports that. `NextRun` counts from the last attempt, successful or not, so a failing destination is retried once per interval; the loop in `cmd/kysignon` polls this every minute and needs no restart after a change.
- `ClearPairing` (`DELETE /api/admin/backup/pairing`) deletes the URL and sealed-token rows from `system_settings` and nothing else: the key pin, receipts and the local directory stay, and a half-cleared pairing is cleared too. It does not scrub the database file (no `secure_delete`), so a snapshot taken afterwards may still carry the ciphertext; the credential is dead only when the KyRecovery admin revokes it (`POST /api/pairing/revoke`), which the product token cannot reach. Re-pairing is accepted only to the same key.
- `PinKey` (`POST /api/admin/backup/pin-key`) is the offline path to `StoreRecoveryKey`: the base64 public key from the ceremony page plus its k-of-n. Same write-once rule as pairing; a different key is 409.
- Text from outside the process (remote error bodies, operator-typed URLs) goes through `AuditSafe` before it reaches an error string or an audit record: printable only, 200 characters.
- Restore drills seal to a throwaway key generated and discarded within the same call, extract into an ephemeral `0700` directory wiped on return, and report only checks they actually execute: file presence, SQLite integrity, required tables, an active admin, secret decryption, token signing.
- KyRecovery connections require HTTPS, follow no redirects, and by default reject private, loopback, link-local and reserved destinations (including carrier-grade NAT, so every Tailscale address). `Config.BackupAllowPrivateRecovery` (`KYSIGNON_BACKUP_ALLOW_PRIVATE_RECOVERY`) admits private and CGNAT addresses for a KyRecovery on the operator's network; loopback, link-local, multicast, unspecified and class E stay refused and HTTPS stays required. `ValidateRecoveryURL` and the dialler take the flag; the pairing audit row records it. The backup client never honours `AllowPrivateCallbacks`: that setting is for paired systems' callbacks.
- `LoadPairing` reports `ErrKeyPinMissing`, not `ErrNotPaired`, when a pairing record exists but `recovery.pub` is gone or disagrees with the pin; the scheduler skips only a never-paired instance and audits everything else.
- No server code opens a capsule sealed to the suite key. `TestNothingInTheServerDecrypts` pins that `recoverykey.Combine` and `FromSeed` are called only inside the `restore` function, and `capsule.Open` only there and inside `RunRestoreDrill`, which opens a capsule sealed to a throwaway key it generated and discards in the same call.
- `ValidateRecoveryURL` refuses a query string or fragment: the API path is appended to the stored URL.
